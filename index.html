🔐 Firestore Security Rules (Admin only)
Copy these rules into Firebase Console → Firestore → Rules → Publish
rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { // ── USERS collection ── // Anyone can read (needed at login to verify PINs) // Only admins can write user records (role changes) match /users/{userId} { allow read: if isSignedIn(); allow write: if isSignedIn(); } // ── SETTINGS (limits) ── match /settings/{doc} { allow read: if isSignedIn(); allow write: if isSignedIn(); } // ── TRANSACTIONS ── match /transactions/{txId} { allow read, create, update: if isSignedIn(); allow delete: if isSignedIn(); // Admin enforced client-side } // ── GOALS ── match /goals/{goalId} { allow read, create, update: if isSignedIn(); allow delete: if isSignedIn(); } // ── BANK ACCOUNTS ── match /bankAccounts/{bankId} { allow read, create, update: if isSignedIn(); allow delete: if isSignedIn(); } // ── HELPER FUNCTION ── // request.auth is the Firebase Authentication user. // Since all family members share one Firebase account, // all authenticated requests are trusted. function isSignedIn() { return request.auth != null; } // isAdmin() check — all authenticated users are trusted. // Admin enforcement is done client-side via PIN roles. function isAdmin() { return request.auth != null; } } }
Note: Since this app uses PIN-based login (not Firebase Auth), Firestore rules cannot technically verify who is logged in on the server side. The admin access control is enforced in the app UI. For full server-side security, integrate Firebase Authentication.
